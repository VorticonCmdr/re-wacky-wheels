# WF: the screens between the race-type menu and the first race of the single player cup, and the cup progression (lead, not fact)

Everything below is tag WF. "[read]" = instructions read; "[inf]" = inferred from context, not read as such; "[pic]" = from decoding a picture. State words are `obj2+0x....` words (16 bit unless said) at the offset given. Routine starts are `obj1+0x....`.

## 0. Corrections to the task text (what the code says)

- **Order.** The vehicle screen comes BEFORE the class menu, not after the race-type menu: the single player entry calls `obj1+0xa380` (`call` at obj1+0xfd7f), and that one routine runs the vehicle screen first and, once a driver is chosen (its state 4, obj1+0xbc55), the four setup menus in order class (`call 0x9eac`, obj1+0xbd3c), laps (`call 0xa148`, obj1+0xbd4b), engine (`call 0x67d8` with eax=2, obj1+0xbd5f), race type (`call 0x6664` with eax=2, obj1+0xbd87) and then the cup board (`call 0x832c`, obj1+0xbdd9). This agrees with the PROVEN `menu.tree-observed` ("the vehicle screen comes before the first and the cup board after the last").
- **Names.** The racer table (obj2+0x5ac..0x5e0, copied to obj2+0x1d228 + 12 x slot by obj1+0x6aac) reads UNO, SULTAN, MORRIS, PEGGLES, RAZER, **RINGO**, BLOMBO, TIGI for the slots 0 to 7 (obj1+0x6aac to +0x6b13); there is no BINGO.
- **The cup names** drawn in the board pictures are "BRONZE WHEELS RACE", "SILVER WHEELS RACE" and "GOLD WHEELS RACE" [pic: SB1.PCX rows y 5-14, 18-27, 31-40]; "Krazy Wheels" is not in them. The preview picture of track 1 carries the text "BRONZE WHEELS" in its bottom band [pic: SHRINK1.PCX].
- **BRONZEM.SP / SILVERM.SP / GOLDM.SP / BONUS?.SP are not the cup board's or the preview's maps.** They are the in-race minimap strips (78 x 50 = 3900 bytes each, five per file, 19500 bytes), see section 7.4. The cup board's five small maps are part of the board picture SB<cup>.PCX; the preview map is SHRINK<track>.PCX.
- **The leaderboard points are 9/6/3 only for the amateur class**; the pro and champion classes award 12/9/6 and 15/12/9, and places 4 to 8 get 0 (section 9.2).

The loop (obj1+0xfff3 to +0x100c5) [read]: `c08 := 0; call 0x7928; if not escaped: call 0x1fd8c; if (c08 == 3 && class != 4) { race++; goto the c08 := 0 line }; else { escaped := 0; call 0x832c (cup board); if the board did not set escape goto the top of the loop (obj1+0xfff3) else back to the main menu }` (obj1+0xfffd, +0x10006 to +0x10028, +0x1003c to +0x10084, +0x100b9, +0x100c0). **Escaping from the track preview therefore does not leave the game flow: the card returns with the escape word set (obj1+0x7f29), the race is skipped (obj1+0x1000b), c08 is 0, the escape word is cleared (obj1+0x10050) and the cup board is called (obj1+0x10063), which zeroes all points and sets race := 1 (6.2); only an Esc on the board reaches the main menu.** The same happens when the race routine returns with c08 = 0 (LEAVE RACE, out of tries, cup finished). `0xbe3c` is called only before the first pass (obj1+0xffee, skipped when obj2+0x28c98 is not 0, the restored-game flag), so the opponents are drawn once per session and survive a return to the cup board.

## 2. Primitives the screens use (so that the sections below can be read)

- **Pages.** The screen is VGA mode X; four 16000-byte pages at the offsets 0, 0x3e80, 0x7d00 and 0xbb80 (80 bytes a row). The word obj2+0x28b24 is the page drawn into AND the one the page flip shows: obj1+0x27de0 writes it to the CRTC start address registers 0xc and 0xd, waits for retrace and copies it to obj2+0x28b18 (obj1+0x27df3 to +0x27e1a). obj1+0x26f14 copies one page (0x3e80 bytes, latches) from the page word obj2+0x28b1c to the one in obj2+0x28b1a (obj1+0x26f29 to +0x26f47). obj1+0x275cd decodes the picture whose PCX run-length body the buffer in obj2+0x1d714 holds (a byte with both top bits set is a count in its low 6 bits, followed by the value, obj1+0x27606 to +0x2760e, +0x2766b to +0x27672) into the page obj2+0x28b24: 320 pixels by 200 rows, one pixel at a time with the sequencer map mask rotated (obj1+0x275cd to +0x276d5, row stride word obj2+0x28b4a).
- **Picture loader obj1+0x17060** (eax = member name, edx = buffer index): reads the 0x80 byte header, then size - 0x380 bytes (the RLE body without the header and the 0x300 byte palette, so the buffer is not raw pixels) into the buffer whose pointer is obj2+0xa978 + 4 x index (obj1+0x17099 to +0x170ca). Indices 0, 1, 2 are the dwords obj2+0xa978, +0xa97c, +0xa980. A member's palette is read separately: obj1+0x418c finds the member, then the code seeks to (offset + size - 0x300), reads 0x300 bytes and calls obj1+0x16ec4, which divides every byte by 4 (obj1+0x16ecc to +0x16edc); the sites are obj1+0x84f4 to +0x8537 (cup board), +0x1ca0c to +0x1ca42 (rostrum) and +0x17c06 to +0x17c46 (the track palette into obj2+0x1d718).
- **Fades.** obj1+0x22cf8 (eax = target palette) fades from black up to it in steps of the byte obj2+0x28c46 (obj1+0x22d51 to +0x22dbb); obj1+0xbf94 (eax = palette) fades that palette down to black with the same step (obj1+0xc017 to +0xc060); the callers save the live palette first with obj1+0x26cca (reads the DAC into the buffer in obj2+0x1d760, obj1+0x26cd1 on), e.g. obj1+0x7df3 to +0x7e07.
- **Text.** obj1+0x48f4 (eax = x, edx = y, ebx = string, ecx = mode): OFONT.SP 8 x 8 glyphs, advance 8, claims `text.char-map` and `text.glyphs-observed`. obj1+0x46d4 (same arguments): WFONT1.SP 15 x 13 tiles, advance 11 (obj1+0x4732, +0x4877), the glyph pointers at obj2+0xa888, claim `text.menu-observed`; centred text is placed at x = (320 - 11 x length) / 2 (obj1+0x1b2f9 to +0x1b30a, obj1+0xcb7b to +0xcb8c) or (320 - 8 x length) / 2 for OFONT (obj1+0xa44f to +0xa46b).
- **Banner obj1+0x1a414** (eax = string, edx = y or 0): a box 8 x length + 8 wide and 16 high, centred in x, at y = edx (0x5c = 92 when edx is 0), with the colours 0x26 and 0x2c, and the string in OFONT at (x + 4, y + 4) (obj1+0x1a41e to +0x1a4a8). **Message box obj1+0x1a268** (eax = number of lines, edx = wait mode, ebx = ticks): lines are the 60 byte records from obj2+0x1c854 on (stride 0x3c), box width 8 x first-line length + 8, height 9 x lines + 8, centred on both axes, lines at (x + 4, y + 4 + 9 n); it waits ebx ticks of the 136 Hz clock (edx = 0) or for a button (edx != 0, via obj1+0x17920) (obj1+0x1a2cc to +0x1a3c5).
- **Buttons and keys** (claims `input.buttons`, `input.key-handler`, `input.steer-flags`): fire words obj2+0x28b40 (button 1), +0x28b42 (button 2), +0x28b44, +0x28b46 filled by obj1+0x277ae; the key bytes obj2+0x28cce (Enter or Space), +0x28cdb (Up), +0x28cd2 (Down), +0x28cd0 (last scancode, 1 = Esc, 0x3b = F1); the steer flags are the high bytes of key table words 0 and 1: left obj2+0x1b6d9 + 12 x player, right obj2+0x1b6db + 12 x player (obj1+0xabc5 to +0xabde). obj1+0x4b00 is called once a frame before the buttons are read [inf: input set-up]. obj1+0x178c4 (eax != 0) waits until every button and Enter/Space is released (Esc aborts); obj1+0x17920 (eax = mode) clears the four button words, then returns 1 when Esc is the last scancode (mode != 0) and 0 as soon as Enter/Space or any button is down; mode 2 also gives up after obj2+0x1e720 >= 0x440 = 1088 ticks (obj1+0x17924 to +0x179e6). Ticks: obj2+0x1e720 counts 136 a second (`tick.rate`).
- **Actors.** The vehicle screen and the menus' corner cars share a table of 12 byte entries at obj2+0x13938: +0 word driver slot, +2 facing, +4 x, +6 y, +8 delay word, +0xa frame word (obj1+0x4264 to +0x4322, obj1+0xa4b1 to +0xa58d). The twelve frame pointers of each CARS.SP slot are the 0x98 byte records at obj2+0x13c08 (`cars.slot-records`, PROVEN), a frame being 38 x 28 = 0x428 bytes.

## 3. Single player entry, obj1+0xfb0e [read]

1. Clears obj2+0x28c22, +0x28bce, +0x28be2, the dword +0x1ec74, +0x1ec90, +0x28c58; sets cup +0x28bb6 := 1, race +0x28b88 := 1, escape +0x28b9e := 0, +0x28b4a := 0 (obj1+0xfb0e to +0xfb61).
2. Decodes the picture in the buffer obj2+0xa978 (the RLE body of CHECK.PCX, loaded by the main menu [inf]) onto the page 0x7d00 (`[0x28b24] := 0x7d00; [0x1d714] := [0xa978]; call 0x275cd`, restored afterwards, obj1+0xfb6a to +0xfb92). That page is the clean background of the vehicle screen. [CHECK.PCX is the menu background, `menu.screen-model`; the vehicle screen redraws that page every frame.]
3. If a save exists (obj2+0x174e4 not 0, or obj2+0x17558 for two players) obj2+0x28c98 := 1 or 2 and the menu " RESTORE SAVED GAME " (obj2+0x1190) / " START NEW GAME " (obj2+0x11a8) is shown through obj1+0x55c0 (obj1+0xfbd3 to +0xfc35); item 2 clears the save flag (obj1+0xfc6f to +0xfc8d). In the restore branch (obj1+0xfd89 on) the saved words replace the settings (see 9.8) and only the engine menu is called (obj1+0xfed0 to +0xfede).
4. Normal path: `call 0xa2f8; call 0xa380` (obj1+0xfd7a, +0xfd7f), then `jmp 0xfee3` which, for the single player, passes through obj1+0xff72/+0xffbc/+0xffe4 to `call 0xbe3c` and the loop of section 1.
5. Escape in the vehicle screen, the four menus or the cup board (obj2+0x28b9e = 1 on return from obj1+0xa380) goes back to the main menu: the CHECK.PCX background is reloaded and obj1+0xf878 is entered (obj1+0xff7c to +0xff83, +0x1008a to +0x100c5).

### 4.3 Main loop and keys (obj1+0xaae0 to +0xb939) [read]

Per pass (single player, not link): read the buttons of the player's key table (`[0x1d8a4] := [0x1d8ac]`, `call 0x4b00; call 0x277ae`, obj1+0xb280 to +0xb299); button 2 counts as fire (obj1+0xb3a0 to +0xb3b3); Enter or Space is fire (obj1+0xb3b3 to +0xb3c5); the player's left key byte sets obj2+0x28cd5, the right key byte sets obj2+0x28cdd (obj1+0xb3c5 to +0xb3e4); Esc as last scancode sets obj2+0x28cec (obj1+0xb3eb to +0xb3f5), F1 opens the help. Then:

- Esc: `obj2+0x28b9e := 1`, return (obj1+0xb52e to +0xb54c): the setup is abandoned and the main menu comes back.
- Fire, while the ring is idle (`[0x150] == 0 && [0x14c] == 0 && [0x130] == 0`): obj1+0xb54d to +0xb576 go to obj1+0xb939 ("chosen"): for every entry whose frame word is 2 or 6 the facing word +2 takes that value (obj1+0xb944 to +0xb972), sound number = the driver slot is played (`call 0x1c04` with eax = slot, obj1+0xb974 to +0xb987), the state word `[0x164] := 1`, `[0x110] := 1`, `[0x15c] := -1` (obj1+0xb97c to +0xb9ae).

## 8. Opponents, obj1+0xbe3c to +0xbefd [read]

So the eight racers are the eight drivers, racer 0 the player, the others a random permutation of the rest; the table obj2+0x10720 is saved with the game (9.8) and the field +0x26 of each racer record (obj2+0xaab6 + 0x68 n) carries the slot [inf from obj1+0x1c08f and the leaderboard]. Racer 0 of the observed starts `race.start-observed` had the slots 7, 3, 2, 1, 6, 4, 0, 5.

## 9. After the race

### 9.1 The player's three tries [read]

At the start of every race the human records (the HUD/car records obj2+0x8410 and obj2+0x8514, stride 0x104, pointer obj2+0x1d5b0) get +0x6c := 3 (obj1+0x1fe55 to +0x1fe8c; obj2+0x847c = 0x8410 + 0x6c is drawn as the digit at (118, 11) of the top banner and read 3 in `hud.banner-observed`). So the "3" of the HUD is the number of tries (continues) left [read the writer; the display is `hud.banner-observed`].

### 9.2 Finishing order and points [read]

- Each racer's finish: when its lap word equals laps + 1 and its place word (obj2+0xaab0 + 0x68 n) is 0, the dword-counter obj2+0x28c60 is incremented and becomes its place (1-based finishing order); a place of 1 to 3 calls obj1+0x2770 (obj1+0x2e3c to +0x2e60 for the player, +0x2efe to +0x2f25 for the others). The counter is zeroed at the start of the race (obj1+0x201db).
- After the player has finished (flag obj2+0x28c3c != 0, set by the lap rule `lap.rules`) and at least three racers have finished (obj2+0x28c60 >= 3; for the time trial it does not wait) the results are fixed once (obj2+0x28c3c := 2, obj1+0x218a0), obj2+0x1ea6c := the tick counter (obj1+0x218a9) and the per-race points array (8 words, zeroed at obj1+0x2017b to +0x201a1) is filled: for each racer n by place 1, 2, 3 the words `obj2+0x1ed58`, `obj2+0x1ed54`, `obj2+0x1ed50` (obj1+0x2182a to +0x2186c); other places leave 0. The three words are set by class obj2+0x28bb2: **1 (amateur): 9, 6, 3; 2 (pro): 12, 9, 6; 3 (champion): 15, 12, 9** (obj1+0x2179d to +0x217bb, +0x217bd to +0x217db, +0x217dd to +0x217fb); class 4 sets nothing. If the player is in the first three the praise line is chosen by `call 0x1d264` (obj1+0x21896; text 9.6).
- After 800 ticks (`obj2+0x1e720 - obj2+0x1ea6c >= 0x320`, about 5.9 s, with the page word at 0x3e80, obj1+0x21919 to +0x2193d) the next step depends on the player's place (obj2+0xaab0): **place 1 to 3 goes on at obj1+0x21cf0** (obj1+0x21945), place 4 and worse is handled in 9.3.
- obj1+0x21cf0 to +0x21d1e: for racers 0 to 7 the racer's points word (obj2+0xaaae + 0x68 n) += that racer's entry of the points array. **Points are therefore kept in the word at +0x1e of each racer record (obj2+0xaaae), racer n = slot obj2+0x10720[n]**, and they are cumulative over the five races of a cup (cleared by the cup board, 6.2). The player's total goes to the dword obj2+0x1ed5c (obj1+0x21d29 to +0x21d39). (The two player branch obj1+0x2150c to +0x215f8 awards 9 - place from the HUD place words obj2+0x84bc + 0x104 n instead.)
- Then (obj1+0x21d3e to +0x21e38): page copy and flip, `call 0x1adc` (sound reset), and for a class other than 4: if the bonus flag obj2+0x1ec80 is not 0 then race := 5 and the flag := 2 (obj1+0x21d8d to +0x21da9); `obj2+0x28c08 := 0` when the race is 5 (cup finished) else 3 (obj1+0x21da9 to +0x21dc7); the palette is copied (obj1+0x21dc7 to +0x21dfb); `call 0x1bff0` (the leaderboard and rostrum); afterwards if obj2+0x1ec80 is 2 it becomes 0, and if it is still not 0 (the bonus was just offered) race := 4 and `obj2+0x28c08 := 3` (obj1+0x21e06 to +0x21e2f), so the loop's `race++` makes it race 5 again, now the bonus race. Class 4 (time trial) calls the hall of fame obj1+0x1e4b8 instead (obj1+0x21e42 to +0x21e98).

### 9.3 Failing to be in the first three [read]

When the player's place is above 3: `obj2+0x28c08 := 0`, the tries word (racer record +0x6c) is decremented (obj1+0x21950 to +0x21959, `call 0x19e0c`). If it is now 0 and the race is 5 or the bonus flag is set, the points step above runs anyway (obj1+0x2196e to +0x21983); if it is 0 in races 1 to 4 the race routine returns at once (obj1+0x21993, jump to obj1+0x227aa, the epilogue) with c08 = 0, so the loop calls the cup board again (the cup is over). Otherwise (tries left) a menu through obj1+0x55c0: item 1 " TRY TO QUALIFY " (obj2+0x1a3c; race 5: " TRY AGAIN " obj2+0x1a50), item 2 " LEAVE RACE " (obj2+0x1a14), and item 3 " SAVE AND QUIT " (obj2+0x1a28) only when class != 4, not kid mode, not the bonus race, single player (obj1+0x219cd to +0x21a5e). Item 1 restarts the race (jump to obj1+0x2006a, the same track, tries already decremented), item 2 returns (obj1+0x21ce1 to +0x21ceb), item 3 writes the save (9.8).

### 9.4 The leaderboard, obj1+0x1bff0 and obj1+0x1b270 [read] [pic]

1. ## 10. The cup progression as pseudo-code

```
single player:
  cup := 1; race := 1                                   // obj1+0xfb46, +0xfb4f
  vehicle screen -> driver slot                         // obj1+0xa380
  class, laps, engine, race type menus                  // 0x9eac 0xa148 0x67d8 0x6664
  cupBoard()                                            // obj1+0x832c
      points[0..7] := 0; bonusFlag := 0; race := 1
      choose cup 1..3 with Up/Down, fire confirms, Esc -> main menu
  opponents := random permutation of the other 7        // obj1+0xbe3c, once per session
  loop:
      track := (cup-1)*5 + race + (bonusPack ? 21 : 0); if (cup==1 && bonusFlag && race==5) track := 7
      card: banner " LOADING RACE n " / FINAL / BONUS!; load; show SHRINK<track>.PCX; wait for a button (not for the bonus race)
      if Esc on the card: skip the race, c08 := 0 -> cupBoard() (points and race reset) -> loop;  a second Esc on the board -> main menu
      tries := 3
      race                                              // obj1+0x1fd8c: countdown, driving, finish; sets c08
      places 1,2,3 -> award T1,T2,T3 by class (9,6,3 / 12,9,6 / 15,12,9), others 0
      if player place > 3:
          tries--                                       // 9.3
          if tries == 0:
              if race < 5 and !bonus: c08 := 0 (cup over) -> cupBoard() -> loop
              else: go on to the points step below (this player's award is 0)
          else menu: TRY TO QUALIFY (TRY AGAIN in race 5) = run the same race again; LEAVE RACE = c08 := 0 -> cupBoard() -> loop; SAVE AND QUIT
      points[n] += award[n]
      leaderboard after race n (ORDER.PCX, sorted by points)    // obj1+0x1bff0
      if race == 5:
          if champion && bronze cup && player on podium && bonusFlag != 2:
              notice box; bonusFlag := 1; race := 4         // then race++ -> the bonus race, track 7, no wait on the card
          else:
              rostrum; if winner (group 1) name entry + FAMOUS DRIVERS board
              c08 := 0 -> cupBoard() -> loop
      race := race + 1; goto loop
```
