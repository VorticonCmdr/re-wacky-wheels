# WF: menu and screen flow of WW.EXE (lead, not fact)

Everything here is tag WF (subagent output). Method: `ndisasm` listing of `analysis/ww/obj1.bin` via `npm run disasm`, string references taken from `analysis/ww/fixups.json` (object 1 site -> object 2 target), archive member names from `parseDatDirectory`. Nothing was run in DOSBox. Offsets are `obj1+0x...` for code and `obj2+0x...` for data (disasm prints obj2 operands as bare numbers, e.g. `0x28bda` = obj2+0x28bda). Citations are `WW.EXE:obj1+0x... fp=...` (from `npm run cite`; fingerprints below are copied from it). "Inferred" marks claims I did not read straight from instructions. Function boundaries were guessed from `call` targets and prologues (`push ebx..ebp`), so a "function" below can be a larger region than named.

## 0. Tools-level facts used

- Menu strings are fixed 16-ish byte blanks-padded records in the first 0x3f80 bytes of obj2. They are copied (rep movsd + movsw + movsb, 22 bytes) into a menu item array at obj2+0x1bc3c, +0x1bc78, +0x1bcb4, ... (stride 0x3c) before the menu routine runs; e.g. the main menu builder obj1+0xf760 copies obj2+0x10b8, 0x10d0, 0x10e8, 0x1100, 0x1118, 0x1130, ... to obj2+0x1bc3c, 0x1bc78, 0x1bcb4, 0x1bcf0, 0x1bd2c, 0x1bd68 (read: `WW.EXE:obj1+0xf760 fp=121ce0a0`).
- Generic menu routine: `obj1+0x55c0` (fp=466094c4). Arguments (inferred from the callers): eax = number of items, edx = initial selected item (callers pass the word obj2+0x28bda), ebx = mode (0 normal, 1 / 2 used by the car/zone variants; `cmp bx,2` at the top), ecx = 0 / item-count-related. It returns the 1-based selected item in eax (0 = escaped; callers then `jmp` back to the menu start). Style id of the box is set beforehand in obj2+0x28bb0 (values 1, 2, 5, 6, 0xd, 0xe, 0x10 compared inside 0x55c0; the sub-menus set 0xd, e.g. obj1+0x11001).
- Helpers seen in every screen (names are mine, behaviour inferred from call context): `0x17060` load PCX by name (eax = obj2 name offset, e.g. 0xe80 CHECK.PCX) after the archive-member loader `0x418c` + palette helpers `0x422c/0x4238/0x4218/0x424c/0x16ec4`; `0x26cca`/`0xbf94`/`0xbf80` clear/prepare the draw buffer (called at the start of nearly every screen); `0x275cd` copy the buffer to the VGA screen; `0x22cf8`, `0x178c4`, `0x17920` palette fade out/in; `0x48f4`, `0x26f14`, `0x26fd0` draw text / measure text; `0x27de0` poll input once (`0x277ae` fills the button words, `0x4b00` something per frame); `0x14c8` wait; `0x1dd30` exchange one input byte with the remote machine (modem/serial play); `0x32160/0x3219c/0x1834` modem helpers; `0x1adc`/`0x1c04` sound start/stop (inferred).

## 1. Input model used by every menu

Read in `obj1+0x55c0`:
- Poll: `call 0x277ae` at obj1+0x5c0a (fp=c3204b27). Then (obj1+0x5c0f..0x5c3c) if the key-table word at obj2+0x1b6dc (player 1 button 1 key) is held and its scancode is 0x48 (Up) or 0x50 (Down), the fire word obj2+0x28b40 is cleared (so the arrow keys do not count as fire); the Enter/Space flag byte obj2+0x28cce (claim `input.key-handler`) sets obj2+0x28b40 = 1 (`WW.EXE:obj1+0x5c33 fp=857ca513`).
- Down flag byte obj2+0x28cd2 -> obj2+0x28cd3 = 1 (`obj1+0x5c45 fp=56c1dfed`); Up flag byte obj2+0x28cdb -> obj2+0x28cd6 = 1 (`obj1+0x5c55 fp=3077afdd`).
- Esc: last scancode obj2+0x28cd0 == 1 sets the latch dword obj2+0x1ecc0 = 1 and the loop waits for key release (`obj1+0x5c65 fp=94b5e181`).
- The loop then packs one input byte into obj2+0x28cf0: bit 0x01 = up, 0x02 = down, 0x04 = fire word obj2+0x28b40 nonzero, 0x40 = Esc latch (obj1+0x5c96..0x5cd7, `fp=997dbbf6` at 0x5cd7); obj2+0x28cf3 = 1 when the last scancode is 0x2e ('C', chat key in modem play; `obj1+0x5d31 fp=7472d056`). That byte and the 'C' flag go to `0x1dd30` (call at obj1+0x5d4c, fp=4f6505ba) which swaps it with the remote side and returns the remote's menu command in obj2+0x28c14 (non-zero means the remote chose; the main menu then uses obj2+0x28c22 as the remote's selection, obj1+0xfa13). Inferred: this is how "REMOTE IS CONTROLLING MENU" works.
- So the default Enter-only path = Enter (or Space) = fire. F10 is the "wait/pause" flag obj2+0x28ccd used by `while (flag) wait` loops after each screen (e.g. obj1+0x24716); idle timers use obj2+0x1e720 (frame counter) and obj2+0x1ed0c (menu idle counter).
- Intro/info pictures are skipped by Enter/fire, by Esc (`[0x28cd0]==1`) or by their timeout (0x6, 0x64, 0xbb8, 0x7d0 ticks in obj2+0x1e720) (obj1+0x24736, 0x24a52..0x24a9e).
